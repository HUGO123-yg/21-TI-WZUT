# 第 21 届轮腿穿越组视觉与组合导航架构

## 1. 赛题事实边界

轮腿穿越组是室外赛，规则允许 GPS，但不允许 RTK。当前公开细则包含三个独立科目：

1. **行进绕桩**：去程先直行到掉头区，回程穿过 `N` 个锥桶形成的 `N-1` 个间隙；锥桶最小间距 1.5 m，数量和场地长度不固定。
2. **定点排雷**：雷区为约 1 m 见方的白色胶带框，胶带宽 10 cm；车辆需在雷区内至少旋转两周且车轮不能越出白色边框。官方问答明确现场可能存在其他白线干扰，因此视觉只能作局部校正，不能作为唯一定位来源。
3. **颠簸路段**：交错单边桥、颠簸条、人工草地、三级台阶/坡道的摆放顺序可能变化。台阶和单边桥下方按规范铺蓝色背景，但台阶中间表面颜色可能作为现场变化项，不能只依赖固定灰度。

官方问答还确认轮腿组允许使用不带 MCU 的磁力计模块和 ToF 模块。由此，工程上应采用“惯性/轮速连续传播 + 视觉局部约束 + 必要时 GPS、磁力计或 ToF 辅助”，而不是让单一灰度相机承担所有绝对定位。

## 2. 模块边界

数据流固定为：

```text
MT9V03X frame
    -> Vision_frame: 唯一相机所有者、曝光、80x60缩放、稳定帧发布
    -> Vision_pipeline: 主循环中每个帧号只分发一次
       -> Terrain_vision: 道路几何、地形候选和置信度
       -> Cone_vision / Minefield_vision: 各自独立消费同一帧
    -> Perception_fusion: 新鲜度、视觉低通、IMU物理支持、导航引导建议
    -> Mission_perception: 导航窗口、标定、新鲜度和科目语义门控
    -> Control_system: 唯一动作仲裁者
    -> Bridge/Bumpy/Jump/Rotation/Balance/Leg/Wheel

IMU + wheel feedback
    -> Navigation: 200 Hz 位姿连续传播和路线记录/回放
    -> Perception_fusion
```

约束：

- `Vision_frame` 是唯一允许调用 MT9V03X 驱动和修改曝光的模块。
- `Vision_pipeline` 是唯一实时观察器调度层，图像算法不进入 200 Hz 控制中断。
- `Terrain_vision` 和 `Perception_fusion` 不调用任何动作模块。
- `Perception_fusion.suggested_yaw_rate_rad_s` 当前只是观测结果，不自动写入 `Control_system`。
- `Mission_perception` 只在对应导航里程窗口内解释对应检测器；不同科目
  的视觉结果不会互相触发。
- `Control_system` 只调度融合服务并记录状态；未标定前不消费视觉引导建议。
- 锥桶、雷区和地形识别应是独立检测器，共享相机帧但不共享内部状态机。
- 视觉失效或超过 `PERCEPTION_FUSION_VISION_TIMEOUT_MS` 后，引导立即降级为惯导输出。

## 3. 当前已实现

- 地形识别：normal、step、bridge、bumpy、obstacle、lost。
- 共享相机前端：采集、缩放、曝光、混帧丢弃和双缓冲发布。
- 实时管线：一次相机服务、按帧号去重，并向三个观察器分发同一不可变帧。
- 道路几何：近端中心、远端中心、归一化横向误差、归一化朝向误差、质量和有效标志。
- 双缓冲发布：控制调度只能读到完整的一帧结果。
- 视觉-惯导融合：新帧去重、视觉超时、低通、IMU支持度、融合置信度和建议偏航角速度。
- 锥桶观测：明/暗两种极性的梯形连通域候选、相邻候选间隙中心和质量。
- 雷区观测：白色闭合边框候选、中心偏差、最近边界行；孤立白线只发布
  `boundary_visible`，不会伪装成闭合雷区。
- 科目上下文融合：锥桶间隙和地形道路建议必须同时满足导航窗口、视觉
  新鲜度和标定门；雷区两周进度由连续航向解包累计，反向旋转会扣减进度，
  航向异常跳变不计入圈数。
- 主机回归：共享帧去重、六种合成地形、道路几何符号、明/暗锥桶、
  雷区白线拒绝、科目里程门、两周航向解包、IMU支持和视觉超时降级。

`Cone_vision` 与 `Minefield_vision` 已通过 `Vision_pipeline` 在主循环处理实时帧，
但仍发布 `calibrated=0`，因此没有加入动作仲裁。现有
`terrain_vision_init/task` 只是兼容入口，内部转发给整条管线；三个观察器仍
保持独立状态。这个标定门是有意保留的：合成帧只能验证接口、几何符号和
拒绝逻辑，不能证明真实锥桶颜色、阴影和白色胶带阈值。

`Mission_perception` 已在 200 Hz 控制调度中服务，但 `Control_system` 默认不
消费它的建议。启动路线 1/2/3 时会分别原子发布绕桩、雷区、地形上下文；
停止路线、故障和急停都会清除此上下文。任务上下文包含路线号、科目、里程
来源、有效窗口，以及当前雷区的旋转方向和不少于两周的目标。当前三类门控为：

| 科目 | 惯导职责 | 视觉职责 | 可用条件 |
| --- | --- | --- | --- |
| 绕桩 | 长距离去返、里程窗口、基础偏航率 | 锥桶候选和间隙中心 | 窗口内 + 新鲜 + 已标定 + 质量达标 |
| 排雷 | 到达雷区、航向解包、净旋转圈数 | 闭合框、中心和近边界警告 | 窗口内 + 新鲜 + 已标定；圈数不依赖视觉 |
| 颠簸 | 连续位姿和基础偏航率、接触后 IMU 支持 | 道路几何和地形提前量 | 窗口内 + 融合有效 + 已标定 |

路线动作也区分比赛语义：`ROUTE_ACTION_MINE_ROTATE_CW/CCW` 只能用于
路线 2，参数小于两圈会被路线配置校验拒绝；动作开始前要求雷区已居中且边框
保护有效，旋转中边框丢失或接近边界会中止。`ROUTE_ACTION_STAIR_DESCENT_JUMP`
只能用于路线 3，避免把单边桥误配成跳跃。上述动作接管默认关闭，待实车
标定后再启用 `MISSION_PERCEPTION_MINE_ACTION_ENABLE` 并配置路线动作点。

## 4. 后续实现顺序

1. **采集真实图像**：白天顺光、逆光、阴影、湿地、蓝布、白/蓝/其他颜色台阶各采集一组；同时记录 IMU、轮速和人工标签。
2. **相机标定**：确认安装高度、俯仰角、水平视场和图像左右符号；在此之前保持归一化图像误差，不换算米或弧度。
3. **科目三优先**：用真实帧校准现有地形检测器；视觉负责提前量，IMU负责接触后的物理确认。
4. **科目二雷区**：用实拍标定已有闭合边框与孤立线拒绝接口；惯导负责到达预记录区域，视觉只完成框内居中和边界保护。
5. **科目一锥桶**：用现场锥桶实拍筛选已有明/暗梯形候选并标定阈值；惯导或 GPS 负责长距离去返，视觉只负责最后的间隙对准。
6. **受控接管**：完成抬轮符号测试、低速直线测试、失帧测试后，才在任务决策层增加视觉引导使能；不得直接从检测器写电机指令。
7. **雷区逐个验收**：每个雷区配置独立路线动作点，每次动作重新开始两圈
   累计；先验证框内居中和边界中止，再开启自动旋转。

## 5. 实车验收门槛

- 摄像头连续运行 10 分钟无混帧，`dropped_frame_count` 可解释且不持续增长。
- 道路向右时两个归一化误差的符号与配置约定一致。
- 遮挡镜头超过 250 ms 后，`guidance_valid` 必须清零，建议输出退回导航基值。
- 科目三每个元素至少采集 30 次接近、进入、离开序列，统计误报、漏报和触发提前量。
- IAR Debug 配置重建 CM7_0 成功；随后在 CYT4BB 目标板验证相机中断、200 Hz 控制时序和轮端输出没有回归。
